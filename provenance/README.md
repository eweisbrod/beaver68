# provenance/

JAR-policy replication artifacts produced by `src/005-data-provenance.{py,R}`.

| File | Description | Tracked in git? |
|---|---|---|
| `sample-identifiers.parquet` | One row per firm-quarter in the final analytic sample, keyed by `gvkey`, `permno`, `rdq`, `datadate`, `fyearq`, `fqtr`. | No (gitignored by default) |
| `sample-identifiers.csv` | Same content as the parquet, in CSV for tools that don't read parquet. | No (gitignored by default) |

A reviewer with their own WRDS access can use these identifiers to
verify the final sample without re-running scripts 001–004.

## How tracking works

By default the template's `.gitignore` excludes `sample-identifiers.{parquet,csv}`
so the template stays clean as it gets passed around. The files are
regenerated by 005 on every pipeline run and are specific to whoever
ran it.

When you are ready to submit your replication package, force-add
the artifacts you want to ship alongside the code:

```bash
git add -f provenance/sample-identifiers.csv
# optionally also the parquet for tools that prefer it
git add -f provenance/sample-identifiers.parquet
```

For a reference copy from the author's own run (useful for replicators
who want to confirm an exact-row match), see the `provenance/` folder
in the [`example-project` hub repository](https://github.com/eweisbrod/example-project).

## What ships with the JAR submission

The 005 script's `.log` (or `.Rout`) under `log/` contains the
end-to-end execution log plus SHA256 hashes for every raw, derived,
and output file. Together with the force-added sample-identifier
files in this folder, that log is what the
[*Journal of Accounting Research's* Data and Code Sharing Policy](https://onlinelibrary.wiley.com/page/journal/1475679x/homepage/data-and-code-sharing-policy)
expects at submission.
